How resume.yml becomes resume.ephemeral-roles.net

rust-operator is a Kubernetes operator written in Rust with kube-rs. You apply one Webpage with a full HTML document in it. The operator then builds what is needed to serve that document publicly. Click any box in the diagram, or play either flow.

The input resume.yml · 


      
    
        
  • Validated by the API server before the operator sees it: html ≤ 102,400 chars and must start with <!doctype html> (a CEL rule); replicas 0–10, default 1.
    • 
        
  • Idempotent: every reconcile rebuilds all desired objects with pure desired_* functions and applies them again. The operator writes only status on the Webpage, never spec.
    • 
        
  • To update the site, edit spec.html and apply again. The ConfigMap changes, and the kubelet syncs the new file into the running pods without a restart.
    • 
        
  • Where the operator runs: a one-replica Deployment in the rust-operator namespace, from a distroless image, as non-root with a read-only root filesystem. Its ClusterRole has no delete verb anywhere; garbage collection removes children through owner references.

Known gaps (MVP, ahead of LEARN.md steps 11–19): deleting the Webpage doesn't remove wp-resume, because a cluster-scoped Namespace can't have a namespaced owner.
    The children are owned by the Namespace, so .owns() never maps their changes back to the Webpage. If the pods aren't ready when it reconciles, the operator waits for the next change to the Webpage, so readyReplicas can stay out of date.
    No status conditions, Events, finalizers, metrics or leader election yet.
    Source: ewohltman/rust-operator (src/lib.rs, src/main.rs).
